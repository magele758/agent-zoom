# 任务怎么执行，问题怎么回到你

任何能调用本地 CLI 的 coding agent 都能发起任务。你可以让 Grok 写计划、Codex 实现、另一位 agent 做独立评审。每个项目阶段都能这样分工。遇到问题时，你从 Zoom 看见「进展到哪一步」和「现在轮到谁」，也能从任务打开执行现场。[看执行流程图](flows.html#execution) · [返回产品导读](../OPC_OS_PRODUCT_INTENT.md)

## 从提案到验收

| 发生什么 | 谁接手 | 留下什么 |
| --- | --- | --- |
| 提交目标、约束或结构化草案 | 发起者带上项目、阶段、原会话和稳定的请求标识。OPC OS生成或接收计划，校验依赖与评审覆盖 | 同一请求对应一个任务。计划写明每个节点的材料、拟用 agent、能力和验收条件 |
| 确认计划 | 你可以指定执行者或采用能力推荐。批准、要求修改、拒绝均绑定具体版本，修改意见回原任务 | 只有获批版本能启动。新版本只能调整尚未启动的下游节点，旧决定和证据可读 |
| 领取与实现 | OPC OS按依赖派发。Herdr 组织会话、pane 和隔离 worktree，各项实现能在各自的范围内并行 | 每次尝试记录执行者、工作树、代码差异和实际测试输出。pane 可定位对应看板 |
| 评审与返工 | 独立评审者读取上游差异和测试，在单独工作树复测。失败时把意见送回对应实现任务，再次交付后复审 | 每轮各存证据，可回看原问题、改了什么、谁核对过 |
| 最终验收 | 你根据当前版本的评审证据决定是否接受交付 | 关闭本次运行，保留执行现场。合并、推送、部署与清理另行授权 |

OPC OS复用已有协调器，以 SQLite 保存计划、认领、租约和回执。重启、租约过期、终端空闲或退出时，先凭尝试标识核对原会话和回执。已收到的结果只登记一次，回执不明的任务等待对账。任务完成以交付证据和验收为准。

## 在项目 room 点名 Bot

在左侧「项目讨论室」点「关联房间和 Bot」，依次选择 OPC OS 频道、Agent Home 中已有的活动讨论房间，以及一个明确的房间成员。人可以从页面发言。已加入频道的 coding agent 也能用自己的房间身份从本机接口发言。OPC OS 保存两端的消息和会话标识，来源相同的请求只投递一次。

有新回答时，Zoom 的最近动态会显示原讨论，Bot 以「待我答复：」标记的问题进入待处理。你在 Zoom 的答复会引用原问题，回到同一房间并点名同一 Bot。送达回执和 Bot 随后的回复分开显示，断线时可以从原讨论核对。正式阶段派工另有目标、交付物和验收条件。

## 在 Zoom 回复，会发生什么

| 你的动作 | 反馈发往哪里 |
| --- | --- |
| 提交计划意见 | 发起者的原任务。显示计划版本、意见和是否送达。本机看板直接决策，无需输入决策密钥。已读、归档单独记录 |
| 回答 Bot 的问题 | 提问的 Bot 和原帖。界面分别显示已保存、已送达和已回复，能点回原消息 |
| 补充实现要求或要求返修 | 对应执行者及尝试。在线 pane 可继续发送。已退出时检查原会话能否恢复，只能新开时由你决定是否交接 |

Grok 的原流程先设计，再在独立 worktree 并行实现与评审。agy（Antigravity）按能力选人并保存会话位置，`hflow fix` 能把返修送回仍在运行的原 worker。OPC OS应让人看清每次选择的宿主、接收人和回执。这些原生入口与OPC OS的接入状态见[验收记录](verification.md)（本机宿主脚本参见 `~/.grok/skills/herdr-split-tasks-router/SKILL.md`、`~/.agents/skills/herdr-flow/SKILL.md` 与 `~/.local/bin/hflow`）。


内置执行器可以把 Grok、Antigravity、Cursor Agent 和 Codex 用在同一份获批计划中。[CLI 执行器配置与验证](cli-runners.md)
