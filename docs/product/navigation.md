# 页面怎样跳转

**主动开工，从公司总览进入。需要你回答，从 Zoom「待我处理」进入。** 两个入口指向同一份项目与任务记录。以下是目标交互。[打开页面跳转图](flows.html#navigation) · [返回设计导读](../OPC_OS_PRODUCT_INTENT.md)

## 从公司总览进入项目

详情页保留总览、Zoom 和公司目录。一个想法可以关联多个产品，展开产品可以看到旗下项目。要找共用能力，可以跨产品按层级、领域筛选。点进事项后，仍能沿「公司 / 产品 / 项目」返回。

| 当前页面 | 点击后去哪里 | 返回时保留什么 |
| --- | --- | --- |
| 每日复盘 | 公司总览 → 信息与想法 → 记下想法 → 选日期、搜索并引用日记原文 → 保存想法 | 想法详情保留日期、小节、摘录和原文链接 |
| 想法详情 | 「让 agent 研究这个想法」打开已选事项的工作单；关联一个或多个产品后，在产品下建立项目、起草 PRD 或加入研发候选 | 选题中的来源链接回到同一想法，其他产品的关联继续保留 |
| 产品详情 | 打开旗下项目，或创建一个尚无仓库的项目。项目首页显示来源想法、目标、阶段、房间与关联仓库 | 回到原产品。由总览进入时也能恢复刚才的筛选 |
| 项目房间 | 在成员里选入 Agent Home Bot，点名提问，答案回原帖。选「转为任务」才进入正式派工 | 任务可回到原问题，查看当时引用的材料 |
| 项目阶段 | 点研究结论可留存或用于开发。点「独立复测」等工作，可填写验收、选择执行者并查看任务。空阶段也有开工入口 | 从计划、差异和测试证据返回同一任务与尝试。已绑定执行现场时可定位 Herdr pane 或 Home 任务 |
| 项目成果 | 点「看这版的效果」查看采用反馈或渠道转化。点「引用到其他项目」可挑选版本，并写下采用方怎样验证 | 可从证据回到该次发布、原想法和日记，也可从来源项目查到谁采用过 |

## 从日读进入学习与研发

在「信息与想法」左侧按日选择 daily-review-learning，右侧阅读整份 Markdown，用目录在章节间跳转。选中内容后可以送入 Learn Agent，继续使用它已有的阅读和学习功能。

读到可以验证的问题，直接写「想验证什么」并保存。记录保留日记出处，可从「已保存」打开。在同一页选择产品和项目，点「派给项目研发」。已有工作区且项目有空位时，OPC OS为这条记录起草可审批的研发计划，页面可直达该计划。工作区未绑定或项目已有在办计划时，委派会保留并显示原因。通过原仓复用要求后才开计划，计划批准后才允许 Herdr 启动执行。

## 从个人工作看板接回项目

**一天从两处读起。** daily-review-learning 留下今天看到的材料，个人版 Agent Hub 汇总今天实际做过的工作。从总览、侧栏或某条业务线进入「工作投入」后，选日期读取公开日报，选择一条工作，关联既有产品下的项目与可选业务线。已关联记录能回到原日期或业务线。详细会话与仅本地可见的主线留在个人看板。[联动流程图](flows.html#hub) · [打开本机 Agent Hub 看板](http://127.0.0.1:28790/)

**从当天工作进入项目。** 选一条工作记录，可点「回到当天看板」核对活动，或选「关联已有项目／任务」带入原始出处。有历史事项标识时可直达它的时间线。如果想据此安排新工作，点「转为任务」并明确目标、执行者及验收。个人看板根据会话与 Git 推断的「已完成」「卡住」供参考，OPC OS按原任务的证据和决定更新进展。只有确需你判断的问题进入 Zoom。

**从项目回看投入。** 项目复盘列出已关联的工作日期、任务和可查证的投入，点日期可回个人看板。订阅摊销、平台超额和按 API 价格折算的用量各列口径，营收与记账仍按订单、收退款和凭证核对。当天快照刷新后更新同一日期，归属不清的工作由你关联，原有决定保留。（快照与投入口径参见本机 `~/.agent-hub/README.md` 与 `~/.agent-hub/src/agent_hub/cost.py`。）

## 从 Zoom 回答一件事

打开消息先看到所属项目、为什么找你、流程阶段、现在轮到谁。处理完回到刚才的待办筛选和列表位置。

| 你点的消息 | 打开的位置和动作 |
| --- | --- |
| 执行者或 Bot 的提问 | 直达原问题。回复前看得到接收人和目标会话，回复后能区分已保存、已送达、待对账。可以从 Zoom 回到原帖继续讨论 |
| 确认计划 | 同页展开对应版本的计划、依赖和证据。批准后才可按该版派工。要求修改或拒绝时，意见回原任务供发起者处理。旧版本只能查看和跳到当前版，已读与归档只改变收件箱状态 |
| 是否继续投入 | 直达项目复盘。先看原目标、实际采用或经营证据、已知投入及缺项，再选择继续、调整或暂停。新提案另行确认执行，发布也单独授权 |

## 三条验收路径

1. **开工。** 当日日记 → 记下启发 → 选择 PageLens 项目 → 验证一个重放样例 → 采用结论开发 → 独立测试 → 授权发布 → 另一项目引用这版测试夹具。
2. **只看消息。** 待我处理 → 「哪些字段必须阻止提交？」 → 看依据 → 回复原实现会话 → 查送达回执 → 返回剩余待办。
3. **回看投入。** 总览 → 原想法 → 比较两个项目的验证结果 → 查看一版发布的反馈或渠道事件 → 记录继续、调整或暂停的理由 → 回原想法看决定和下一位负责人。


## 从任意事项委派

| 从哪里进入 | 点下去后发生什么 | 在哪里看结果 |
| --- | --- | --- |
| 消息、工作流卡片、项目阶段或房间里的原问题 | 选择已有执行人，或填写 coding agent 在 CLI 使用的名字，写下调查范围、做法与验收依据 | 「委派台」显示待认领、已接手与回执。可返回原事项 |
| 原计划审批、原仓变更需求、经营复盘 | 委派执行者先核对，交回建议与证据 | 「待我处理」打开原版本或原实验，由你提交决定 |
| 想法、研发候选、经营实验或仓库详情 | 从当前页面带入具体项目和对象，生成一项独立工单 | 委派记录保留来源链接。原有研发计划继续遵循项目审批 |
| 后续待处理消息 | 在「委派台 → 默认办理方式」选择执行者和办理说明，启用自动办理 | 后续新待办按该方式派发；开启前已有的事项仍可逐条委派 |
