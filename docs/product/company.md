# 公司、产品与项目

从公司总览打开一条想法，就应当看见它来自哪篇日记、可能用于哪些产品、哪些项目已经试过。工作再多，你也可以只开 Zoom，处理所有项目里等你答复的事项。[设计导读](../OPC_OS_PRODUCT_INTENT.md) · [业务流程图](flows.html#business)

## 公司目录怎么排

| 所在位置 | 在这里记录什么 |
| --- | --- |
| 公司 · 信息 | 引用 daily-review-learning 的日记条目或专题。读材料时可以还没有产品 |
| 公司 · 想法 | 记下自己的判断和待验证问题。一个想法可以引用几条材料，也可以关联多个已有或拟建产品 |
| 产品 | 记录为哪些人持续解决什么问题。一个产品可同时开展维护、新特性和商业验证项目 |
| 产品下的项目 | 记录这一次的目标、成果、负责人和阶段。GitHub 仓库是可关联的工程资产，一个项目可以用多个仓库，也可以在写代码前立项 |
| 项目结果 | 将具体版本、投入、使用反馈和下一步决定挂回原想法。同一想法在两个项目的结果可以分别查看 |

从日记出发，也可以直接选已有项目研究或追加特性。新建项目时再选所属产品。所有目录共用全局看板、组织数字孪生与 Zoom。在「商业与治理部」点击「一键纳管公司全景」（或执行 `opc-os commercial bootstrap`）可将 L0–L6 7 层蓝图中的 18 项核心资产一次性导入产品目录并自动标注层级、领域与跨项目复用关系。

## 公司部门

四个职能部门跨产品、跨业务线工作。打开全局看板的「公司部门」或左侧「经营与公司部门」分组可以看全公司，展开项目目录里的具体项目可以直接进入该项目的安全评审或服务记录。

| 部门 | 在这里处理什么 |
| --- | --- |
| [商业与治理部](http://127.0.0.1:52328/#commercial) | 统筹 L0–L6 7 层资产地图、1 号变现试点与聚焦铁律、6 大伴生服务自启动网格（Commerce/GTM/Ops/DuckDB/Home/Hub）、Ed25519 离线 License 签发验签、门面合规与 UTM 推广包、统一客服工单分诊与 5 套业务线打法库。 |
| [安全部门](http://127.0.0.1:52328/#security-department) | 按项目登记一次评审的范围，例如某个版本的权限变更。记录结论和证据，需要整改时保留原发现，修复后提交复审。 |
| [运维部门](http://127.0.0.1:52328/#operations-department) | 实时探查已接入的 6 大伴生服务健康状态与响应延迟。为项目服务记录异常与恢复，登记当前版本、目标版本和更新验证结果。 |
| [资源成本部门](http://127.0.0.1:52328/#resource-department) | 查看 Agent Hub 最近采集的套餐额度窗口和已登记的月费，手动补充其他订阅。派任务前可以逐项核对剩余量、单位、重置时间和数据日期。 |

额度口径沿用来源。同一套餐的短时限额和周限额各占一行，共同约束使用。已过重置点的快照需要新读数才能确认本期余量。委派台提供额度入口，任务仍按你选择的执行者办理。

「重读快照」读取本机 Agent Hub 最近采集的结果。在接有本机采集器的正式服务上，点「采集最新额度」即可按 Agent Hub 的现有配置查询各工具。某个工具暂时取不到数据时，看该工具的核对时间和状态。其他订阅可手工登记金额、币种、月付或年付周期，以及上次查到的余量和日期。

## 日记继续在哪里维护

从公司总览进入「信息与想法」，点击「记下想法」。页面直接读取已有 daily-review-learning 目录中的日期日记。选择日期，搜索关键词，点一条原文，再写下想验证的问题。保存后可以关联多个产品，为每个产品建立项目，或直接用现有项目。保存的内容包括所选摘录、日期文件和小节；原文中的外链可以打开。当日未提交的修改也能读到。本机目录可通过 `OPC_DAILY_REVIEW_DIR` 指定（参见日常库下的 `AGENTS.md` 与 `2026-11-20.md`）。

在想法详情点「让 agent 研究这个想法」，研究单会预选该公司事项。进入产品下的项目后，「起草 PRD」保留产品和项目，「加入项目候选」则将想法的来源证据送到研发选题。重复操作沿用同一条候选。两个项目采用同一想法时，各自保留候选和执行计划。长期专题和原编辑器快捷操作属于后续接入范围。

## 怎样找到别的项目做过的东西

- **按层级找职责。** 沿用你已有的层级名称，在总览筛出提供基础能力的项目，或使用这些能力的应用项目。
- **按领域找同类问题。** 一个项目可同时涉及浏览器和电商。领域筛选跨产品，也可以和层级组合。
- **按成果版本复用。** 在目标项目里引用另一项目的组件、研究结论、夹具或发布流程，注明版本与适用条件。来源方能看到谁引用过，使用方补上自己的验证，并区分「可复用」「已引用」「已验证」。

## 二月的自动工厂怎样接入

MindScroll OS 的原案先让多个 agent 完成一件可审查的工作，再用同一套办法建设工厂自己。原案还追踪分发、支付和用户反馈，让发布结果影响下一轮投入。[自举思路](https://github.com/magele758/knowledge-2-business/blob/497ee275cb43b61b61419c804265398cff057a77/DEVELOPMENT_PLAN.md#L3-L15) · [人机分工](https://github.com/magele758/knowledge-2-business/blob/497ee275cb43b61b61419c804265398cff057a77/DEVELOPMENT_PLAN.md#L332-L357) · [知识与商业闭环](https://github.com/magele758/knowledge-2-business/blob/497ee275cb43b61b61419c804265398cff057a77/DEVELOPMENT_PLAN.md#L383-L412)

旧版 PM Agent 会按技术可行性与付费可能性评分，达到阈值可创任务。OPC OS的建议是让 Bot 从今天的材料找旧项目和失败尝试，写明谁需要它、有什么证据、怎样做一次小验证。你可以留待观察，也可以选项目投入。走通的流程保留每步所需材料、执行者与验收，下一个项目用自己的仓库、计划审批和证据重新运行。[二月 PM Agent 的判断逻辑](https://github.com/magele758/knowledge-2-business/blob/497ee275cb43b61b61419c804265398cff057a77/mindscroll-os/apps/api/src/modules/agents/pm-agent.service.ts#L46-L96)

**建议试点**为OPC OS自己的「从日记引用到项目 room」。用一条真材料验收原文与房间讨论能双向找回，再让第二个开源项目沿用这套分工。日期日记引用、跨产品关联、加入项目候选、以及想法与项目讨论室/阶段工作单的双向跳转均已实现并通过自动化测试验证；真实 Agent Home 房间里的端到端实盘试点仍可按需展开。
