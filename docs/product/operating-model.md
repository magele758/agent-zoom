# OPC OS · 一家公司怎样同时经营几条业务线

公司总览回答「现在做的是哪门生意，值得继续投入吗」。Zoom 收齐需要你决定的事。业务线可以持续增加，每条线描述自己的目标、实际做法和成效。一个产品、仓库或 Chrome 插件可以被多条线使用。每次实验和每笔经营凭据有明确归属。

| | 技术研发 | 自动化店铺运营（探索中） |
| --- | --- | --- |
| 平时从哪里发现机会 | 日记里选中的技术、仓库的新特性和版本、尚未解决的 Issue、用户反馈 | 一次店铺操作的观察、人工操作成本、某个插件可复用的能力、渠道反馈 |
| 系统可以自行推进什么 | 汇集可追溯线索，在启用的项目里说明选择理由，只选下一项，为目标仓库出计划。批准后按依赖开发、测试、独立评审并处理返工 | 在项目下记录「假设、用到哪些插件、观察指标、一次实验的范围」，收回证据。早期每轮可换方法 |
| 什么到 Zoom 找你 | 计划审批、需求取舍、无法恢复的回执、最终验收 | 有材料后决定继续、调整或暂停。批准本次复盘只记录经营决定，实际改价、发布商品等动作另行授权 |
| 如何判断做成了 | 改动与测试、验收、发布版本、真实采用，商业化时再核对收入 | 有来源的观察和投入，按币种分别记录实际收款、退款和费用。没有订单时，用本轮原定的验证指标复盘 |

**同一能力，两处使用。** 店铺项目可以采用 ChromeGate Gateway 已有的场景预检命令，研发项目也能引用同一版本。若接口缺一项能力，店铺项目提交带验收办法的原仓需求。你在 Zoom 批准后，工作进入维护仓库的候选队列。每个采用方保存自己的实验、成果和经营凭据。[版本、页面与审批流](reuse.md)

## 自动选题怎样做决定

每个已绑定仓库的研发项目有自己的候选队列和开关。每条候选保留来源、采用理由、影响、证据把握和工作量。首版按「影响 × 把握 ÷ 工作量」排序。各项取 1 到 5 分，同分按进入时间和稳定来源标识排列。每个项目一次推进一份自动选中的计划，负责人可以先跳过一条线索；已批准的节点、测试和评审按原运行归档。这个排序用于决定先验证哪件事，商业回报由实际采用或交易证据判断。

## 页面与角色

- 公司总览 → 业务线 → 选一条线 → 看目标、关联资产、实验和结果。新线可以直接从一个尚无仓库的经营假设开始。
- 研发选题 → 选择已绑定仓库的项目 → 核对候选与理由 → 选出下一项 → 当前版本计划出现在 Zoom → Herdr 中的实现与独立评审 → 验收。想继续自己原有的 coding-agent 会话，也能从 CLI 提交和收取反馈。
- 店铺运营 → 新建实验 → 登记授权范围、使用的插件与成功条件 → 录观察或收退款凭据 → 提交复盘 → Zoom 回答 → 回原实验看决定。试验得到可复用做法后，再决定要把哪步接成固定自动化。
- daily-review-learning 持续负责资料，Agent Hub 提供个人工作线索和投入依据，Agent Home 提供具名 Bot，Herdr 管理工程执行现场。OPC OS 保留任务与回执，经营实验可直接记观察结果而无需开启代码执行。
