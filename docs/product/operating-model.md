# OPC OS · 一家公司怎样同时经营几条业务线

全局看板与组织数字孪生回答「现在做的是哪门生意、走到哪一步、值得继续投入吗」，**商业与治理部**负责把 1 号商业试点和 6 大伴生服务串成真实收款与漏斗闭环，Zoom 收齐所有需要你拍板的事项。业务线可以持续增加，每条线描述自己的目标、步骤、共用资产与成效；一个产品、仓库、插件或商业套件可以被多条线复用，每次实验和每笔多币种经营凭据都有明确归属。

## 五套标准化业务线打法库

在「商业与治理部」（`#commercial`）或 CLI（`opc-os commercial playbook <模板ID>`）中，可以一键套用以下 5 套业务线打法并自动开启首轮实验：

| 业务线模板 ID | 业务线名称与定位 | 核心验证与闭环方式 | 共用资产示例 |
| --- | --- | --- | --- |
| `core-rd-factory` | **技术研发**（工程底座） | 从日记启发、GitHub Issue 与客服工单自动选题 → Zoom 审批计划 → Herdr 隔离编码与独立评审 → 验收发版回访 | `agent-zoom`、`ppeng-agent-bot`、`chromegate-gateway` |
| `flagship-extension-monetization` | **旗舰插件商业变现**（1 号商业试点 / 首选现金流） | 高转化着陆页与商店隐私合规 → 多平台 UTM 首发 → 去隐私核心动作激活 → MoR 自动签发 Ed25519 离线 License → DuckDB 核算净毛利 | `pagelens-interpret`、`opc-commerce-kit`、`opc-gtm-kit`、`opc-ops-kit` |
| `open-core-prosumer` | **Open-Core 开发者商业线**（高客单复利） | 开源核心自然传播 + 免配置桌面安装包 / 手机远程增值 Pro 授权对照转化，高频工单回流研发 | `audiobook`、`hyper-vibekanban`、`opc-commerce-kit` |
| `automated-shop-ops` | **店铺运营**（受控自动化场景现金流） | ChromeGate `--dry-run` 预检 → 限定范围生成草稿并经人工弹窗确认发布 → 多币种记录收款/退款/费用 → 观察一键转研发候选 | `pagelens-agent`、`chromegate-gateway` |
| `lead-magnet-funnel` | **轻工具流量漏斗**（零成本获客） | 零门槛互动工具承接自然流量 → 挂载 `opc-gtm-kit` UTM 导流条 → Waitlist 沉淀并向旗舰产品输血 | `Rubiks-Cube-Learn`、`bazi-ziwei-learning`、`opc-gtm-kit` |

## 供给研发 vs 商业与经营实验的分工

| | 供给侧：技术研发 | 需求与商业侧：旗舰变现 / Open-Core / 店铺 / 导流实验 |
| --- | --- | --- |
| 平时从哪里发现机会 | 日记里选中的技术、仓库的新特性和版本、尚未解决的 Issue、`opc-ops-kit` 升级的用户缺陷工单 | 市场痛点、渠道内容转化、人工操作成本、某个插件或轻工具可复用的获客/变现能力 |
| 系统可以自行推进什么 | 汇集可追溯线索，按评分在启用的项目里只选下一项，为目标仓库出计划；批准后按依赖开发、测试、独立评审并处理返工 | 生成门面与 UTM 推广包、采集去隐私激活、自动签发离线 License、记录实验假设与多币种收支凭据并同步 DuckDB 漏斗 |
| 什么到 Zoom 找你 | 计划审批、原仓维护需求取舍、安全整改复核、无法恢复的回执、最终验收 | 实验复盘（继续/调整/暂停）、退款或例外授权、发版回访发信；实际改价、发布商品与上线均另行授权 |
| 如何判断做成了 | 改动与测试、安全评审、发布版本与真实采用 | 渠道获客→激活→首单→复购漏斗、按币种扣除退款与 Token/平台费用后的真实净毛利，或本轮原定验证指标 |

**同一能力，多线复用。** 店铺运营可以采用 `chromegate-gateway` 已有的场景预检命令，旗舰插件与 Open-Core 产品共用 `opc-commerce-kit` 的 Ed25519 离线验签与 `opc-gtm-kit` 的着陆页模板。若原仓接口缺少能力，使用方提交带验收办法的原仓维护需求；你在 Zoom 批准后，工作进入维护仓库的候选队列。[版本、页面与审批流](reuse.md)

## 1 号商业试点与组合聚焦铁律

为防止一人公司多线并行分散精力，「商业与治理部」内置 **Portfolio Governance（组合聚焦铁律）**：同一时期只指定 1 个「1 号商业试点」（默认聚焦 `PageLens / pagelens-interpret`，目标定价 `$29 买断 / $19 年付`），通过 7 步闭环就绪清单追踪进展；在跑通「门面 → 获客 → 激活 → 收款发码 → 客服 → DuckDB 复盘」全闭环前，默认开启**冻结新建底层基建仓库**提醒。[7 层架构蓝图](opc-7-layer-blueprint.md)

## 自动选题怎样做决定

每个已绑定仓库的研发项目有自己的候选队列和开关。每条候选保留来源（日记、GitHub Issue/Release、店铺观察或客服工单）、采用理由、影响、证据把握和工作量。首版按「影响 × 把握 ÷ 工作量」排序。各项取 1 到 5 分，同分按进入时间和稳定来源标识排列。每个项目一次推进一份自动选中的计划，负责人可以先跳过一条线索；已批准的节点、测试和评审按原运行归档。这个排序用于决定先验证哪件事，商业回报由实际采用、渠道转化或交易毛利证据判断。

## 页面与角色

- **全局看板 / 组织数字孪生** → 一屏查看所有业务线、公司四部（商业与治理/安全/运维/资源成本）、实时工作现场与 13 阶矩阵。
- **商业与治理部** → 一键纳管 7 层全景、一键拉起 6 大伴生服务、一键演练首单闭环、签发验签离线 License、生成门面与 UTM 推广包、分诊客服工单并同步 DuckDB 漏斗。
- **公司业务线** → 选一条线或套用打法库模板 → 看目标、共用资产、多轮实验与多币种凭据 → 提交复盘到 Zoom，或从观察一键转为研发候选。
- **研发选题** → 选择已绑定仓库的项目 → 核对候选与理由 → 选出下一项 → 当前版本计划出现在 Zoom → Herdr 中的实现与独立评审 → 验收。
- **协同底座** → `daily-review-learning` 持续负责资料，`Agent Hub` 提供个人工作投入与套餐额度，`Agent Home` 提供具名常驻 Bot，`Herdr` 管理隔离工作树执行现场，`OPC Commerce/GTM/Ops Kit` 与 `data_analysis` 承接商业与经营分析闭环。
